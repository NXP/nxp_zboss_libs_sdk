Zigbee stack migration guide: v3.3.x to v4.0.0

This page describes required changes to successfully migrate from the ZBOSS stack v3.3.0 (r22 codebase) to ZBOSS stack v4.0.0 (r23 codebase). It is supposed that application using ZBOSS v3.1.0 has been already migrated to ZBOSS v3.3.0. Read this page alongside the ZBOSS section of the Zigbee release notes. This section lists all the changes in the ZBOSS stack v4.0.0 that are related to the stack.

To migrate, complete the following steps:

  1. Read the page about new r23 features - ZBOSS Zigbee 2023 (r23) features
  2. If you want to switch off new r23 functionality and keep r22 behavior, look at Runtime switch of r23 ZBOSS into r22 mode.
  3. Read the section about changes in panid conflict resolution PANID conflict resolution API
  4. If the application manually adjusts configurable memory settings, be aware of new setting ZB_CONFIG_NWK_DISC_TABLE_SIZE
  5. If the application manually adjusts configurable memory settings, be aware of new setting ZB_CONFIG_ZDO_KEY_NEGOTIATIONS_NUM
  6. If the application operates directly with ZBOSS neighbor table entries (the unusual case), be aware of changув format of zb_neighbor_tbl_ent_t and introducing zb_nwk_disc_tbl_ent_t.
  7. To build ZBOSS from sources without ZB Direct support need to have ZB_LITE_NO_ZB_DIRECT defined.
  8. To switch off multimac building ZBOSS from sources need to have ZB_COMPILE_MAC_MONOLITHIC defined
  9. Note that device can be put into Restricted mode when some ZDO commands may be not accpted - Restricted mode. All Hubs Restricted vs WWAH Configuration mode.
Warning
The NVRAM version has been changed. The data stored in the NVRAM on your device will be automatically migrated to the new version at first ZBOSS start. Updating of ZBOSS r22 based FW to r23 based FW via OTA is possible.
